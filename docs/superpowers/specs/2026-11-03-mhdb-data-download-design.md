# MHDB データ取得設計

## 目的

Monster Hunter Wilds の装備最適化に必要な MHDB Wilds Data の加工済み JSON を、出典と取得内容を追跡できる形でローカルへ取得する。第三者データをこのリポジトリから再配布せず、同じ入力を再取得できることを優先する。

## 対象範囲

- 固定した上流コミットから `Armor.json`、`Accessory.json`、`Amulet.json`、`Skill.json` を取得する。
- raw JSON は `data/raw/mhdb/<commit>/` に保存し、Git 管理外とする。
- 出典リポジトリ、上流コミット、取得日時、各ファイルの URL・サイズ・SHA-256、ライセンス情報をローカルの manifest に記録する。
- ダウンロード途中のファイルを完成品として残さず、HTTPエラーやチェックサム不一致時は失敗として終了する。
- この段階では JSON の正規化、ゲームデータの内容検証、Python-MIP との接続は行わない。

## 採用方式

必要な加工済み JSON のみを GitHub の固定コミットURLからHTTPSで取得する。上流リポジトリ全体のcloneは、不要な抽出ツール、Windowsバイナリ、巨大な補助ファイルまで取得するため採用しない。追従先が暗黙に変化する `main` 直指定も再現性がないため採用しない。

取得CLIには既存の Python 3.12 環境を使い、標準ライブラリだけで実装する。テストではネットワークへ接続せず、HTTP取得部分を差し替えて保存・ハッシュ・manifest生成・失敗時処理を検証する。実データ取得はテスト通過後に一度実行し、JSON構造と件数を読み取り専用で確認する。

## ライセンスと公開方針

- `data/raw/` と、その中に生成されるローカルmanifestは `.gitignore` で除外する。
- リポジトリにはダウンロード処理、取得元定義、利用者向け説明だけを置く。
- MHDB Wilds Data が GPL-3.0 であることと、ゲーム由来コンテンツに別の権利が存在し得ることをREADMEに記す。
- 将来コミットする正規化データは、最適化に必要なID・数値へ限定するかを別途判断する。raw JSONを正規化データへ複製する設計にはしない。

## 成功条件

- 一つのCLIコマンドで4ファイルを固定コミットから取得できる。
- 再実行しても同じ内容になり、manifestから各ファイルを検証できる。
- raw JSONが `git status` に現れない。
- 取得失敗時に壊れた完成ファイルや成功manifestが残らない。
