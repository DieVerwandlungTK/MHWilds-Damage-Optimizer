# Combat Skill Effect Resolution Design

## Intent

装備実現可能性モデルが返すスキルレベルを、双剣の単一コンボ火力に必要な攻撃力、属性値、会心率、会心倍率、直接ダメージ倍率へ変換する。常時効果と条件付き効果を同じ仕組みで解決し、既存の `calculate_combo_damage` へ渡せる検証済み入力を作る。

対象ゲームバージョンは Ver.1.042 系とし、具体的な基準は `1.042.00.03` とする。MHDBの固定コミット `c50a1eb892f4a1ad9bb35c147801658804be2cc2` にあるスキルID、種別、ランク、ゲーム内説明を同定に使い、Ver.1.042までの公式更新情報で変更有無を確認する。効果値が説明文や一次資料から確定できない場合は推測しない。

## Goals

- `FeasibleBuild.effective_skill_levels` と手入力武器から、ダメージ計算用能力値を決定的に生成する。
- 常時発動、対象状態から自動判定できる条件、利用者が明示する条件を一つの宣言的な効果表で扱う。
- 効果の加算、乗算、会心率上限、会心倍率、適用順序を明示する。
- 各効果定義に対象バージョン、出典、検証状態を持たせる。
- 発動条件または数値が不明な火力スキルを無言で無効化せず、利用者へ具体的に報告する。
- どのスキルのどの効果が適用されたかを結果から追跡できる。

## Non-goals

- 防御、生存、快適性、スタミナ消費量、アイテム持続など、直接コンボダメージを変えない効果。
- 毒、麻痺、睡眠、爆破などの状態異常蓄積と発症ダメージ。
- 斬れ味ゲージ長、斬れ味消費、研磨、業物、達人芸の時間推移。1回の評価では入力された現在の斬れ味色を使う。
- ボウガン、弓、ガンランス、狩猟笛など双剣以外に固有の弾、矢、砲撃、旋律効果。
- 抜刀、溜め、ガード、空中攻撃など、乱舞 I～III に適用されない攻撃種別限定効果。
- 傷付け蓄積、部位破壊蓄積、追加ダメージ発生までの蓄積、一定確率の追加ヒットなど、現行の単一コンボモデルで決定できない効果。
- ゲーム内丸め順序が未検証のまま `game_exact` を有効化すること。

## Anti-goals

- 「わずかに上昇」などの文言から任意の数値を割り当てない。
- 条件未指定を `false` とみなして、発動可能なスキルを黙って無効化しない。
- 候補間比較に使えないスキルを無視したまま、結果を火力最適または候補内ベストと表示しない。
- スキル名の文字列で効果を参照しない。正規化済みの安定IDを使う。

## Approaches Considered

### 1. Declarative effect table plus condition resolver — selected

スキルID、ランク、条件、補正をバージョン付きデータとして定義し、共通エンジンが適用する。効果値の監査とアップデート差分を追跡しやすく、単純スキルを専用コードなしで追加できる。特殊な計算順序だけをPythonで扱う。

### 2. One Python handler per skill

複雑なスキルには柔軟だが、条件、数値、適用順序がコードへ散らばる。Ver.1.042以降の更新差分と出典確認が難しくなるため採用しない。

### 3. Ask callers for already-resolved stat modifiers

実装は小さいが、装備スキルから火力を評価する目的を満たさない。テスト用の低水準入力としても公開しない。

## Effect Data

`mhwilds_optimizer/data/skill_effects/1.042.00.03.json` を組み込みデータとして追加する。ゲーム由来の名称や説明全文は複製せず、次だけを保持する。

- `schema_version`
- `game_version`
- `sources`: URL、参照日、対象範囲、検証状態
- `skills`: 正規化スキルIDをキーとするランク別の効果節
- `unsupported`: 火力へ影響するが、数値または現行モデルでの評価方法が確定していないスキルIDと機械可読な理由
- `non_damage`: 現行の双剣単一コンボ火力を変えないことを確認したスキルIDと機械可読な理由

各効果節は条件と、一つ以上の補正を持つ。初期スキーマで扱う補正は次とする。

- `raw_flat`
- `raw_multiplier`
- `affinity_points`
- `element_flat`
- `element_multiplier`
- `positive_critical_modifier`
- `raw_damage_multiplier`
- `element_damage_multiplier`
- `positive_element_critical_modifier`

補正値はJSON numberを直接floatへせず、文字列から `Decimal` として読む。ランクは1から正規化スキルの `max_level` 以内でなければならない。効果表ロード時にスキルID、スキル種別、ランクの連続性、補正種別、有限値、条件キー、出典参照を検証する。

ゲーム内説明で数値が明示された、双剣の直接火力へ適用可能な効果を最初の対応対象とする。例として攻撃、見切り、五属性攻撃強化、超会心、弱点特効、挑戦者、攻勢、逆襲、巧撃、逆恨み、フルチャージ、火事場力、渾身、力の解放、無我の境地、濡れ刃紋、攻めの守勢、鈍器使い、および数値を確認できるシリーズ／グループ効果を含む。

連撃、災禍転福、会心撃【属性】、属性吸収、属性変換、追加ダメージ型のシリーズ効果など、説明文だけでは値または計算方法を確定できないものは、一次資料または再現可能な実測根拠を得られるまで `unsupported` とする。実装時の調査で値を確認できたものは、出典と検証状態を添えて通常定義へ移す。

## Conditions

条件値は「真／偽／未指定」を区別する。自動判定できる条件は入力から導出し、それ以外は `SkillConditionState` へ明示する。

自動判定する条件:

- `monster_enraged`: 評価対象のモンスター状態。
- `target_weak`: 斬肉質が45以上。
- `target_wounded`: 傷口状態。
- `sharpness_at_most`: 現在の `Sharpness`。
- `weapon_element`: 武器の属性種別。

明示入力する条件の初期集合:

- 体力最大、体力35%以下、赤ゲージあり。
- スタミナ最大。
- 狂竜症克服。
- 毒または麻痺中の対象（両方を一つの真偽値として扱い、攻勢を二重適用しない）。
- 状態異常中のハンター。
- 回避成功後、被弾後、拘束解除後、鍔迫り合い／相殺成功後、ジャストガード後。
- 肉などのアイテム使用後。
- 水濡れと泡状態（同時発動時はそれぞれの効果を加算）。
- 力の解放の発動中。
- 連続攻撃の段階など、対応数値が確認できた時点で必要となる列挙状態。

同じ条件に自動値と明示値の両方がある場合は、一致しなければ入力エラーにする。自動判定できない必須条件が未指定なら `MissingSkillConditionError` とし、暗黙に不発へしない。

## Resolution Model

`SkillResolutionContext` は武器、対象肉質、怒り／傷状態、明示条件を持つ。`resolve_combat_stats(...)` は次の順序で処理する。

1. `FeasibleBuild.effective_skill_levels` を受け取り、効果表の対象ランクを決定する。
2. 非火力スキルは無視し、適用可能な火力スキルの各条件を解決する。
3. 基礎攻撃力へ `raw_multiplier` の積を適用し、その後 `raw_flat` の和を加える。
4. 武器属性と一致する効果だけについて、基礎属性値へ `element_multiplier` の積を適用し、その後 `element_flat` の和を加える。
5. 会心率へ `affinity_points` を加え、-100から100へ制限する。
6. 正会心倍率、属性会心倍率、物理／属性ダメージ倍率を解決する。同じ排他的倍率が複数ある場合の規則がデータで明示されていなければエラーにする。
7. 拡張した `CombatStats` と監査情報を `SkillResolutionResult` として返す。

連続近似では途中丸めを行わない。ゲーム内の段階丸めを検証できるまで、この解決結果を使った計算の保証は `continuous_approx` に限定する。

## Damage Model Extension

既存呼び出しとの互換性を保つため、`CombatStats` へ既定値1の次のフィールドを末尾追加する。

- `raw_damage_modifier`
- `element_damage_modifier`
- `positive_element_critical_modifier`

物理ダメージ倍率は物理成分だけ、属性ダメージ倍率は属性成分だけへ1回適用する。属性会心は正会心率にだけ適用し、負会心時に属性値を減らさない。既存テストの `CombatStats` 構築は変更不要とする。

`demon_dodge_buff` は戦闘状態由来であり、スキル効果表へ移さない。既存の物理／属性別係数と新しい倍率を独立に適用し、二重適用をテストする。

## Results and Failure Policy

`SkillResolutionResult` は次を返す。

- 解決済み `CombatStats`
- 適用したスキルID、ランク、効果節、条件根拠
- 条件が偽で不発だった火力スキル
- 無視した非火力スキル
- 最も弱い検証状態と警告

既定はstrictとする。非ゼロのスキルは `skills`、`unsupported`、`non_damage` のいずれかに分類されていなければならない。`unsupported` に登録されている、未分類である、必要条件が未指定、または対象バージョンが一致しない場合は解決を停止する。`non_damage` のスキルだけを監査情報へ記録して無視する。調査用のnon-strictモードでは警告付きで返せるが、その結果は候補ランキングへ使用できないことを型または明示フラグで示す。

## Integration Boundary

この作業単位では、1件の `FeasibleBuild` を `CombatStats` へ変換し、既存のコンボ計算で評価できるところまでを完成させる。Python-MIPの代理目的、候補集合生成、Top N、CLIは次の作業単位とする。

後続の候補ランキングはstrictかつランキング利用可能な解決結果だけを受け付ける。未対応火力スキルを含む候補を黙って低く評価してはならない。

## Testing

- 効果表のスキーマ、Decimal変換、ID／ランク／条件／出典検証。
- 常時効果の加算・乗算順序、複数スキル合成、会心率の上下限、属性不一致。
- 弱点特効の肉質45境界と傷口追加分、挑戦者の怒り自動判定。
- 明示条件の真／偽／未指定、同じ自動条件との矛盾。
- 条件不発、非火力無視、未対応火力、バージョン不一致の監査結果とエラー。
- 超会心、属性会心、鈍器使い、鬼人身躱しを含む物理／属性成分の独立適用。
- 武器固有、防具、装飾品、護石、シリーズ／グループ由来のスキルを、由来に依存せず合算済みレベルから解決できること。
- 既存ダメージ計算と武器省略時APIの全回帰テスト。
