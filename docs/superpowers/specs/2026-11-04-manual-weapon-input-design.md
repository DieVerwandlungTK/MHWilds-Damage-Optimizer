# Manual Weapon Input Design

## Goal

完成済みの双剣をデータベースから選ぶ代わりに値で入力し、その基礎性能を既存のダメージ計算へ渡すとともに、武器固有スキルと武器スロットを装備実現可能性判定へ組み込む。

## Scope

- 1回の探索につき、入力された武器1本を固定装備として扱う。
- 武器のID、表示名、基礎攻撃力、会心率、属性種別、属性値、斬れ味、武器スロット、固有スキルを不変モデルで表現する。
- 属性種別は `none`、`fire`、`water`、`thunder`、`ice`、`dragon` を扱う。状態異常は現行のダメージ式が扱わないため対象外とする。
- 武器スロットには武器用装飾品だけを配置する。
- 武器固有スキルと武器装飾品のスキルを、防具、護石、防具装飾品、シリーズ／グループボーナスのスキルに加算する。
- 武器を省略した既存API呼び出しは、武器スロットと武器スキルがない従来どおりの判定を行う。
- MHDBの武器ファイルはダウンロードせず、通常武器とアーティア武器のどちらも完成時点の値を同じ形式で入力する。

以下は対象外とする。

- 武器候補の選択や武器自体の最適化。
- アーティアのパーツ、復元強化、ボーナス、付与スキルの合法構成生成。
- 状態異常値と状態異常ダメージ。
- スキル効果を基礎性能へ反映した最終能力値の計算。
- 武器によるシリーズ／グループ発動部位数への寄与。

## Model

`mhwilds_optimizer.weapon_models` に次を置く。

- `ElementType`: 対応する6種の属性種別。
- `Weapon`: `id`, `name`, `raw`, `element_type`, `element`, `affinity_percent`, `sharpness`, `slots`, `skills`。
- `combat_stats_from_weapon(...)`: 武器の基礎性能と、武器外の会心倍率・鬼人身躱し状態から既存の `CombatStats` を作る。

数値は既存のダメージモデルと同じく `Decimal` を使う。攻撃力と属性値は0以上、会心率は -100 から 100、スロットレベルは1から3とする。`element_type=none` のとき属性値は0でなければならず、属性種別を持つとき属性値は正でなければならない。固有スキルは正のレベルだけを受け付け、入力後は変更不能にする。

武器単体ではカタログを参照できないため、未知スキル、最大レベル超過、武器用でない通常スキル、既存装備と重複する所有者IDはソルバー呼び出し時に検証する。シリーズ／グループスキルは固有スキルとして直接入力できない。

## Feasibility Integration

`solve_feasible_build` と `enumerate_feasible_builds` にキーワード専用の `weapon: Weapon | None = None` を追加する。武器は固定入力なので選択変数を作らない。

武器がある場合は次をモデルへ加える。

1. 各武器スロットに、要求レベル以下の `SlotType.WEAPON` 装飾品を0個または1個配置する二値変数を作る。
2. 武器固有スキルを定数項としてスキル式へ加える。
3. 武器装飾品のスキルを配置変数の項として加える。
4. 復元結果へ武器IDと、武器IDを所有者とする装飾品配置を含める。

`FeasibleBuild.weapon_id` は互換性のため省略可能な値とする。武器を渡さなければ `None`、渡せばそのIDを返す。装飾品配置は既存の `DecorationPlacement` を共用し、`owner_id` で武器、防具、護石を区別する。

列挙時は武器装飾品の配置変数も禁止カットへ含める。同じ防具・護石でも武器装飾品の配置が異なれば別ビルドとして列挙する。

## Damage Integration

`combat_stats_from_weapon` は `raw`、`element`、`affinity_percent`、`sharpness` を武器から取り、正会心倍率、負会心倍率、鬼人身躱し状態を呼び出し側から受け取って `CombatStats` を返す。この変換ではスキル効果を適用しない。したがって、現段階では入力した完成時点の基礎性能を既存の純粋なダメージ関数へ安全に接続する役割だけを持つ。

## Error Handling

- 武器単体の型・範囲・整合性違反は `WeaponInputError` とする。
- カタログとの不整合は既存の `EquipmentInputError` とする。
- ソルバー内部の例外へ変換する前に入力検証を行い、利用者の入力ミスを `SolveStatus.ERROR` に隠さない。

## Tests

- 武器モデルの正常系、不変化、数値範囲、属性種別と属性値の整合性、スロット、固有スキルを単体テストする。
- `CombatStats` 変換が全対応フィールドを正しく渡し、追加の会心倍率と状態を検証する。
- 武器固有スキルだけで要件を満たす場合、武器装飾品が必要な場合、スロット不足、武器／防具装飾品の混在拒否を検証する。
- 未知スキル、最大レベル超過、種別違い、所有者ID重複を検証する。
- 武器省略時の既存挙動と、武器装飾品を含む列挙の重複排除を検証する。
